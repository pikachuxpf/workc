# 连续执行、环境恢复与验收交接

本页约束已获准的修复、交付和运行，不扩大用户指定范围。STANDARD 与 UNATTENDED 都适用；CONSULT、明示静态只读/禁运行及 Skill 维护不启动题包或 Docker。主代理负责把本次必需工作执行到底，阶段汇报不是暂停点。

写范围、答案隔离与独立核验沿 [统一许可合同](qc-exceptions-and-admission.md)，实际取证沿 [运行验收](runtime-acceptance.md)，顺序沿 [执行 SOP](execution-sop.md)；本页不另立通过阈值或审批。

## 1. 未完成项必须有下一步

复用同根 QA 的验收矩阵，不新增审批表。每个未闭合必需项记录实际状态、缺口、下一可执行动作及其依据；尚有已获准、安全、可执行动作时，主代理执行它，不以“可继续”“建议补跑”“请作业员修复”作为最终回复。

| 当前情况 | 下一步 |
|---|---|
| 静态/局部回归通过，正式 verifier 尚未跑 | 核入口与隔离，完成正式运行并核结果 |
| Docker 等已安装能力尚未启动 | 按第2节恢复，就绪后续跑 |
| tests 内 runner/helper/config 有确认错误 | 作业员保全、实际修复、验证并记 QA |
| 当前运行漏留关键证据 | 按运行验收 §4.1 查源；可合法重跑则生产新 run，保留旧 run 未证事实 |
| 独立 QC 返回可修问题 | 核实、修复/补证、补受影响验证、更新 QA、独立复检 |
| 报告已准确写明 NOT_RUN/UNVERIFIED/BLOCKED | 核仍可执行的恢复/补验路径；状态披露本身不完成原门 |
| 单个子代理结束、单条命令超时或会话摘要切换 | 主代理核真实进度，继续剩余工作；不能据此结束整份请求 |

候选分数、运行有效性、评分集正确性、报告质量和外部签收分别判定。正式链健康但候选低分不要求救到满分；也不证明全题规则正确。确认缺陷仍修，真实候选错误保留有效规则。

## 2. 已安装环境未就绪，作业员自主恢复

获准的 Docker 验证隐含普通、可逆的本机启动准备权。主代理启动已安装但停止的 Docker Desktop/对应服务，不修改题包外源码或环境配置；这与“tests 外文件只读”不冲突。独立 QC 保持审核角色，向作业员交接环境恢复需求，不自行管理宿主服务。

1. **先辨故障。** 核实际 CLI 路径、当前连接/context 与 `docker version`/`docker info` 的脱敏错误。区分客户端不存在、daemon 停止、连接目标错误、权限拒绝及后端故障，不能把所有连接失败都判成“未安装”。上下文存在远端或共享服务时先核目标，不为本题启动/重启无关服务。
2. **启动已安装组件。** Windows 先核精确 Docker Desktop 可执行文件的存在及进程状态；未运行则用 `Start-Process -FilePath <已核绝对路径> -WindowStyle Hidden` 启动一次。已有进程但正在初始化时先等就绪；明确需要已安装的停止服务时，通过该安装支持的普通启动机制或 `Start-Service -Name <已核服务名>` 启动。其他主机沿已安装环境的既有启动机制执行，不猜服务名，不盲启所有服务。
3. **有界检查就绪。** 单次探测、等待均有超时，短间隔检查 daemon；Docker Desktop 可先给约180秒启动窗口，按实际启动进展调整。用支持超时的调度方式约束探测命令，不能让一次 `docker info` 无限挂住。每30秒左右给简短进度，不用长时间阻塞等待代替沟通。只有服务端有效响应、目标引擎/OS 满足正式入口才算就绪，进程存在不等于就绪。
4. **未就绪则诊断。** 检查精确相关的非秘密状态/错误，区分启动尚在推进、普通启动失败、权限/UAC或交互要求、后端不可用。每次重试须有状态变化、修正命令或新依据；不要反复启动同一进程、无限轮询或无依据重启。仅窗口超时还不足以宣称永久不可恢复；须核剩余合法路径。
5. **恢复后继续原任务。** 重新预检版本/目标/隔离，回到中断的验证步骤并实际完成后续结果核对、QA 和独立复检。启动成功不能代替正式验收。

同类准备包括选用已安装的正确 shell、纠正当前进程的路径转换/临时输出位置、使用已批准的可用端口和现有镜像；均先核副作用和实际入口，不偷偷换正式版本或评分语义。题包外已批准运行目录可存非秘密运行证据，不存可编辑整题副本、业务实现或补丁来绕过写边界。

本条不许可安装/升级依赖、改 Docker 配置或全局 context、重启正在工作的 daemon/WSL/系统、终止无关进程、清理镜像/卷、重置环境、重启机器或绕过权限提示。遇到此类真实边界，先完成其他可执行工作，再列具体失败动作/脱敏结果、剩余门和所需外部动作；不把尚未尝试的普通启动交给用户。

## 3. 质检入口与证据必须匹配

每次送检先核实际主文档的证据边界、对象与模式，不沿用旧版能力。默认单题 scoring_set + deep；报告质量另列 qa_report 对象；批次/扩展规范仅有采用依据才启用。按正式可见来源建需求原子，逐 criterion 核双向反例及入口→注册/manifest→证据/judge→聚合链，分别记录 B、漏覆盖、框架责任和未证项；本轮 F/N0、A/(N0+A) 不冒充算法 B/N。

当前 `E:/work-C/doc/质检SKILL/qc-qa-report/SKILL.md` 是 strict_static：审核者实际阅读该入口及其要求的共同规则/适用参考；不运行题包、Docker、verifier、judge，也不读运行日志/轨迹/reward。WorkC 通用 QC 的可执行能力不能覆盖所选静态入口的更窄限制。其 `PASS_STATIC_SCOPE`、`audit_complete=true` 或报告措辞准确，均不认证运行门或整题 PASS。

本次需要动态证据复核时，由主代理完成已授权真实验证，并安排未参与修复的独立运行复核，明确模式及采用依据：

- 已指定/采用含轨迹规范时，先按明确已授权路径核 `qc-qa-report-gj` 等实际入口并全文读取，执行其适用门；不能假设名称存在、把隔离历史归档当现行入口，或在静态入口里越界取证。
- 未要求某个外部含轨迹入口时，可另按 WorkC 的运行验收/质检执行合同独立核当前实际运行证据，回执注明 `WORKC_RUNTIME_REVIEW`，不冒称外部算法含轨迹版通过。可由同一仍独立 reviewer 分开执行两种模式，但须明确切换依据、证据范围与各自结论；用户明示静态只读时不切换。
- 明确必需的外部入口确不可得，先合法查源；仍不可得则该外部门未闭合，不能换内部复核冒外部 PASS。继续其他已获准工作，不为找入口搜索禁区或无界遍历工作区。

独立回执绑定实际审核版本与证据范围。反馈中“需要运行/轨迹”交接到主代理或对应合法审核模式，不能转成永远只改 QA 的静态循环。实质修复后复核受影响项，未变有效证据复用。

## 4. 最终回复前的停止闸门

依次核对本次验收矩阵：

1. 所有必需修复、正式运行/必需 judge、逐项/聚合、运行留证、QA 与适用独立审核是否真实闭合；不把局部通过升级成全题。
2. 未闭合项是否仍有获准且可执行的下一步，包括普通环境启动、tests 内入口修复、合法补证/重跑与独立复检；有则继续，不发最终交接。
3. 若确需停止，是否有实际尝试、结果、剩余合法路径为何不可行、受影响门与恢复条件；“没打开 Docker”“未跑正式验收”“报告已披露未证”本身不构成穷尽证明。用户停止、明确预算耗尽或需用户决定的真实权限/目标分歧按其实际边界处理。

只有本次必需项闭合才完成；真实不可继续时如实报受阻且原请求未完成。补丁可交接只说明其已证范围，不是允许放弃仍可执行的完整交付/补验。不得通过删门、弱化规则、只调整 QA 标签或把必需项改“本次未请求”换取通过。长任务使用进度消息持续推进；中断接续先核最后有效证据与下一步，不重做已完成工作、不假定后台已跑。
