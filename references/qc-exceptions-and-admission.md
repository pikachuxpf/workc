# 质检默认许可与材料开工准入

本合同统一 WorkC 的质检默认许可、写范围硬锁和证据准入，适用于标准及无人值守模式；操作顺序见 [WorkC 作业员执行 SOP](execution-sop.md)。修复/交付/无人值守的主 WorkC 是作业员/协调者，负责主动发现、确认、授权修复和验证；本合同的 QC 权限只属于未参与修复的独立 reviewer，不把作业员自查或报告自查改称独立 QC。用户已解除 GT/oracle 静态核查及合法本地 oracle 验证的逐题单独授权条件：进入目标明确的 WorkC 作业后，相关操作依本次范围和作业上限默认许可，不再索要单独 GT/oracle 批准。题包写范围统一按 [主文第2节](../SKILL.md#2-先选本次作业固定验收范围)：作业员可修当前题 `tests/**` 全部内容与同根 QA，tests 外除该 QA 只读移交；instruction 依实际位置分流，不设 tests 内路径冻结或逐文件批准。该许可不启动当前不存在的题包作业，不绕过用户明确只读/禁运行/禁修改要求或工具权限，亦不授权答案外发、读取秘密、平台提交或其他冻结路径。

**环境操作与题包写权分开**：已获准本地运行时，主代理依 [连续执行合同](continuous-execution.md#2-已安装环境未就绪作业员自主恢复) 自主启动已安装但停止的 Docker Desktop/对应服务，核就绪后继续；普通启动无需重复批准，不是修改 tests 外冻结文件。此例外只含既有能力普通启动，不授权安装/升级、改配置、重置、重启工作中服务或绕过权限；独立 QC 不自行管理宿主服务。

## 现行无人值守默认

已有唯一明确当前task，用户仅下达“无人值守”或等价执行指令、无明确更窄/只读/禁写限制时，默认FULL_ACCEPTANCE当前全题tests侧自动修复验收，本请求许可当前题tests/**全部内容与同根qa_report.md写入。worker按主文第2节核实际目标与链接、记录范围映射，无须重复或逐文件批准；明确限制优先，早前仅作业标签不阻新默认，无唯一目标、Skill维护或纯咨询不启动题包。按 [现行路由](routing-and-authority.md)，冲突的旧作业沿用及默认8轮/2轮停止口径不再适用；内部自动核准入、双冻结、隔离及真实验证，不新增逐项审批，也不降低证据接受、答案隔离、外发或候选权限标准。

worker先从允许正式材料独立双冻结，备证、自查修tests并真实验证；默认只读检查当前task tests外相关允许正式材料，把范围及问题路径/证据/影响/责任/移交写同根QA，未发现也记范围，不扫工作区、不读.pipeline/秘密，GT及oracle答案仅独立QC核。完成实质报告后派未参与修复的独立不写题包 QC实际读QC文档，核当前task、本轮报告质量及外侧记录，分别核适用历史失败 A/B；无 always-failing、零缺陷或未改 tests 仍审事实/状态/运行。worker核实反馈、集中tests/QA修复、按技术依赖补适用验证、独立复检对应结论；仅准确追加审核回执不无限自指。无显式预算则持续处理尚有合法可修/补证路径项；重复无效动作须换查证/归因/修法，不因轮数或无进展计数停。只有真实无法继续才STOPPED_BLOCKED对应范围；STOPPED_BUDGET仅显式预算耗尽，尊重用户退出。外侧无关/建议不阻tests通过，真影响必需判据则对应结论BLOCKED/UNVERIFIED/FAIL；tests侧通过与整题外部阻塞分报，移交不算修复、不冒UNATTENDED_COMPLETE。

## 1. 角色、顺序与默认许可

1. 协调者及设计/修复角色从正式 instruction、persona、policy、fixtures 和 materialized carriers 独立推导义务，不接触隐藏答案来定义正确性。先记录 `obligation_freeze_ref`，再固定评分设计、答案空间、判据、部分分、路由及聚合关系为 `scoring_design_freeze_ref`。两份冻结绑定范围、正式版本、来源和时间；同版有效独立记录可重核复用。这是防答案污染的顺序要求，不是待用户批准的授权条件。
2. **独立 QC reviewer** 未参与修复，题包不写；`qc_role` 只记录这个实际 reviewer，不填协调者/设计/修复角色，未派发或不可用如实记。它可按 §1.1 独立执行本次已允许的安全核验。它先从正式输入独立核本次义务和评分设计，再核双冻结；随后可默认静态读取当前题相关根 ground_truth.json 和 oracle 源码，不需要逐题读取授权。记录 `qc_role / qc_read_scope / qc_permission_basis=WORKC_DEFAULT / applicable_clause / obligation_freeze_ref / scoring_design_freeze_ref / actual_reads`。精确对象及适用依据用于范围审计，不是要求用户逐项批准；没有某条外部条款时，当前明确 QC 目标也可作必要性依据，不空造条款。
3. 未双冻结时先完成独立推导/冻结再核答案，不让用户补授权替代独立设计。目标不明不猜题；CONSULT 仅分析，不启动题包核查。READ_ONLY 中实际独立 reviewer 可在上述顺序后静态核相关 GT/oracle，仍不执行、不写；作业员/协调者不能借只读标签获得隐藏答案读取角色。
4. GT/oracle 只用于独立离线 QC 对账，不成为业务义务来源、运行时评分答案依赖、候选输入或普通 judge evidence。协调者/修复角色不直接读 GT、不接收原文、答案、可反推答案的摘录、数值或摘要；reviewer 仅回报正式来源支持的缺陷位置、可推导性、结论与脱敏引用。修法从正式输入独立推出，不根据 GT 改期望到一致，不能把 GT 摘要称为“正式材料”。
5. **本地 oracle 验证默认许可**：当本次作业允许执行，且相关验证确有必要，独立 QC 可按 §1.1 直接在合法隔离入口执行 oracle；协调者也可编排获准隔离运行而不接触答案，不再索要独立 oracle 执行批准。先核最小挂载、版本/副作用、输出隔离与凭据隔离；QC 执行仍不得写题包。READ_ONLY/CONSULT、用户明示禁运行、需要未授权外部调用/秘密或无隔离入口时不执行。oracle 执行不授权普通候选新 rollout，不产生额外写权，不让协调者/修复角色、普通候选或 judge 接触 GT/隐藏答案；合法隔离 oracle 的输出仅由 QC 角色核查，协调者可收脱敏状态/结果引用。确无可满足条件的入口则停止对应运行，不能伪造证据。静态读取本身不等于已完成动态验证。
6. `.pipeline/` 内容对所有参与者始终禁读、禁引用、禁依赖；不得搜索、hash、挂载或通过副本/他人结果绕过。秘密不读、不转写。质检默认许可不授权答案外发或新的外部模型上传；按实际 Agent/运行合同核数据边界，不能向未授权服务发送答案。工具权限拒绝不能以本默认规则绕过。

### 1.1 质检可执行核验，但题包不写

质检不是只能看文本：可非破坏地查询现有环境/版本、解析允许文本、做内存反例与独立复算、运行 Skill 自身检查。本次作业允许执行时，还可独立运行必要且已获准的 parser/回归、正式 verifier-only 或上述本地 oracle，实测当前版本而非只采信作业员结果。角色能力不替代作业授权：CONSULT 不启动题包取证，READ_ONLY、默认静态 REPORT_QC 及明示静态只读/禁运行仍不执行；RUN_ONLY 只限指定模式，局部不升级全题，已有 FRESH 证据足够时不空重跑。

**所选规范更窄时优先**：当前 qc-qa-report 是 strict_static，禁止执行题包或读取轨迹/运行日志/reward；本节通用能力不覆盖该入口。静态与动态按 [质检交接合同](continuous-execution.md#3-质检入口与证据必须匹配) 分开送审，运行主张另走实际已采用的含轨迹入口或标明 WORKC_RUNTIME_REVIEW 的独立复核；外部必需门不能用内部结果替代。PASS_STATIC_SCOPE 不等于本节运行回执或整题 PASS。

- **task 全路径不写**：QC 不修改 tests、根 QA 或其他题包对象，也不生成/应用修复补丁。运行产生的 cache、日志、字节码、临时文件、评分结果及子进程副作用同样不能落入 task；路径别名、链接、挂载和重定向按实际目标判定。协调者仍是唯一题包写入角色。质检可给正式可推导的缺陷位置和修法方向，但不承担修复实现，不把自产补丁换名为核验材料。
- **先核入口，再隔离运行**：核实际 command/mode、版本、允许输入、import/collect、runner 与子进程副作用及输出位置；用已可用的只读最小允许输入挂载或等效强制只读沙箱保护题包，非必要宿主路径不可见/不可写。工作目录、HOME/TMP、cache、日志及结果落入本次获准的 task 外独立隔离工作区，仅供最小探针与核验产物，不放源代码副本、业务实现、整题镜像或 staging/补丁；不搬出禁读材料，隐藏输出遵守下述答案隔离。设置 -B、关闭 pytest cache 或事后 hash 对比均不能单独证明副作用已被阻止；不运行未知入口后再声称没改 task。
- **无安全入口则不执行**：入口必写 task、只读保护不可用、依赖未授权写入/外发/秘密或副作用不可核时，QC 停止该动态项并回报具体限制，由 worker 先核是否为获准且可修的 tests 内入口/runner/helper/config 缺陷；是则按主文第2节备证、实际修复并验证安全入口后复核，不能自动归外部环境移交。确无合法修复/运行路径才限制对应结论；移交不扩大协调者权限，不等于已验证。QC 不自行安装依赖、修改系统/配置、重启服务、删除未知文件、创建题包副本或改 runner 来造入口。已有执行许可不自动授权普通新候选、外部 judge、网络上传、平台提交或读取凭据；工具拒绝不绕过。
- **独立性与答案隔离不变**：GT/oracle 仍先独立义务和评分设计双冻结；相关答案只在获准隔离 QC 边界内核，不进入普通探针、候选、judge、修复角色或未授权模型服务。不得因已有答案暴露给 QC 就让它重新承担独立设计。执行核验不等于参与修复，不能据 GT 调整评分设计。协调者只收正式可推导发现、脱敏状态及可核引用，不收隐藏原文、数值或可反推摘要。
- **回执复用既有表**：记录实际执行者、command/mode/版本、最小输入与只读保护、隔离输出引用、预期/实际、run 及 freshness；未执行标 NOT_RUN/真实阻止，不编运行回执。QC 在回复交证据，根 QA 仍由协调者写。协议/结构检查不认证技术 PASS，也不自动替代正式运行。

## 2. 写范围接口

- 唯一范围定义见 [主文第2节](../SKILL.md#2-先选本次作业固定验收范围)。仅作业员（协调者）写当前题 tests/同根 QA；子 Agent 和 QC 全路径不写。完整修复/无人值守默认全 tests，tests_allowlist 仅作实际映射，用户明确更窄限制优先。
- 写前按该节核规范化实际目标、链接和重定向；完整 tests 范围包括 instruction、runner/验证入口、judge、helper、shim 和 config。范围内确认缺陷须由 worker 实际修复、适用验证并写同根 QA，不以类型标 OUT_OF_SCOPE，不只给建议/登记/移交。真实目标落到 tests 外则不写；相关允许材料的发现直接入同根 QA，列精确路径/版本、证据、影响、责任/移交方和恢复条件，不另建待办替代 QA。仅当前必需依赖缺口限制对应结论，其余记录后继续，不等待外侧整改；移交不算修复或 PASS。明确局部/只读/RUN_ONLY 等上限仍优先；不写业务实现，不创建 sidecar、整题副本或私造补丁产物。
- tests 修改同步唯一根报告，先保全本轮原内容，列真实 diff、正式可推导缺陷/修法及终态。用户明确不允许根报告写入时不改 tests，不用副本绕过；写许可不解除本合同的禁读和答案隔离。
- tests 内正式 instruction 合同的合法修复、或外部有权负责人改变外侧正式合同，沿主文第2节合同变更接口备证/登记，失效受影响证据，由未接触隐藏答案的角色重推并双冻结、重验后交独立 QC；不据 GT 放宽规则，不以新合同追认旧候选违规或改写历史。

## 3. 材料不足前移为开工准入

按 [材料准备](evidence-preparation.md) 建立逐项需求，按结论/作业依赖判定，不把每种历史材料强加给所有作业。开工及收口按 [历史对象与门控统一规则 §7.2](verification-and-reporting.md#72-先发现对象不能用报告自证不适用) 核允许来源，分别记录对象存在性、审核状态和本次必需性，复用既有矩阵。`admission_status=ADMITTED / NOT_ADMITTED / N/A`，记录 `admission_scope / historical_requirements / preimage_refs / future_run_plan / admission_evidence_refs / admission_owner / admission_reason`。准入仅约束实际依赖项，是作业员依据真实证据的核查，不要求用户逐项批准；声明表或辅助工具不能自行认证准入。

- **旧材料准入**：按 [§7.2.1](verification-and-reporting.md#721-历史未证只限制实际依赖的结论) 区分历史修改与旧候选因果，只有该主张必需的 ORIGINAL_TASK 或 HISTORICAL_TRAJECTORY/反馈映射须在依赖作业前 VERIFIED，或由有权方正式接受具体对象/版本/条款的替代；不将两类旧材料捆绑给每个当前主张或同一 attempt scorer。默认操作许可不授权自造历史、由协调者/reviewer 自签证据接受或以当前快照/preimage/指标/新 run 替旧事实。合法恢复与穷尽按中央规则，不启动依赖缺口的循环。
- **本轮写前准入**：每个授权 tests 目标有可核 ROUND_PREIMAGE、起始状态、最小完整修改单元/上下文，合法保存/引用在唯一根报告，原不存在记 ABSENT。无合法保全不写该目标，hash 不等于完整修法证据。preimage 只证明本轮起点，不自动等于权威旧 ORIGINAL_TASK；可信原题恰为起点时按正式来源核身份。本轮已改却漏留为 WorkC 生产缺口，须如实记录、合法查源恢复，相关修法未证，不倒填或推给旧材料灭失。
- **修后运行生产准入**：CURRENT_RUN 分清现有与未来。修前核 `future_run_plan` 的必需入口/模式、本次作业运行范围（必要本地 oracle 记 WORKC_DEFAULT）、合法 evidence 来源、隔离/挂载、版本/依赖/服务、逐项/聚合结果位置和失败处理。普通新候选/外部调用不因默认 oracle 许可开放。先由 worker 处理获准且可修的 tests 内验证入口缺陷，按写前保全和安全要求修验，不以当前入口失效自动否决该入口返修；排除此路径后仍已知无法合法产生必需验证，才不启动依赖该缺口的返修。修前不要求已有修后结果，计划不能填 CURRENT_RUN=VERIFIED，不保证未来服务不会失败。
- **最终验收**：修后实际取得正式 CURRENT_RUN，核身份、真实消费、逐项/聚合、degraded 与 FRESH；计划、预检或 admission=ADMITTED 都不能认证 PASS。真实运行失败或服务变更则重评准入，保留已证范围并停止受影响完成声明。

历史必需性、穷尽后的依赖隔离和旧 QA 纠错统一按 [§7.2.1](verification-and-reporting.md#721-历史未证只限制实际依赖的结论)，不增字段/状态机/权限。只将实际依赖旧材料的项 NOT_ADMITTED；独立当前全题范围继续修验，不退成仅 parser/局部 workaround。无历史必需门且当前全部必需证据通过可当前交付/UNATTENDED_COMPLETE；有明确历史门仍阻原请求全范围认证，不自签替代接受或伪装历史失败。本轮 preimage/evidence 缺失仍属 WorkC 生产缺口。只读仅回复材料审计，不写不运行或称动态成功。

### 3.1 报告生产与质量接口

按 [报告合同 §7.1–7.4](verification-and-reporting.md#7-报告与qc接口) 分本轮报告质量 QC 与历史失败 A/B 归因 QC，最终逐层给范围/依据/状态。所有本轮新写/更新 QA 均质量自查，审范围/来源、缺陷/归因、修法/实际变更、运行/验证/freshness、指标、阻塞与状态；没有失败清单、A/B 表、tests 修改或缺陷仍适用。关键缺陷/修法/有效性主张缺证质量 UNVERIFIED、确证错误 FAIL；准确报告技术或历史未证可质量 PASS，但不等于技术、候选或历史 PASS，不因披露缺口自动通过所有主张。

FULL_ACCEPTANCE/UNATTENDED 有本轮报告写入须未参与修复的不写题包 reviewer 独立质量审核，作为该报告/模式交付必需项；标准局部自查、按影响/风险复核，不新增全题独立门。REPORT_QC 明示窄范围优先，未指定时识别并分别核两层；RUN_ONLY 仅获准报告写入时自查，不扩运行范围。历史层的对象/状态/必需性及完成声明按 [§7.2](verification-and-reporting.md#72-先发现对象不能用报告自证不适用)，不自动阻当前全题/模式完成，不删真门或冒全历史通过。

每个本轮缺陷/实质修法复用技术表、稳定 issue 和轮次引用，留正式依据/精确位置及断言、反例/独立预期、观察/归因、写前完整上下文、实际 diff/终态、适用验证/run/版本/freshness及未证责任，不复制台账。主动静态发现不虚构旧 Agent 行为，未执行标推演/NOT_RUN，未验证不标 FIXED+FRESH。任何报告变更核对应内容；技术仅按依赖变化失效，不空重跑 verifier。先由作业员完成主动自查修验、实质报告及报告自查再独立审；reviewer 实际读取原有权威 QC 主文档及已采用条款，按同一路径/版本/合同核当前 tests、QA 和相关外侧记录，给逐项发现。作业员核实确认授权 tests/报告错误就实际修复，反馈涉及规则/归因/证据则补适用验证并独立复检对应结论；STANDARD 完整验收同样要求独立复核，明确直到 pass/完成交付按请求范围持续闭环，不需额外说无人值守、不自签独立 PASS；局部默认门和其他作业上限不变。最后仅追加准确回执不无限自指。

## 4. 示例与最终声明

- 合法默认读取：明确当前题静态 QC，未逐题授权 GT/oracle；独立正式义务/评分设计双冻结后，独立 reviewer 直接静态核相关对象，只回报正式来源支持的结论，不要求补读取批准。
- instruction 按实际位置分流：明确当前题完整返修，获准正式来源独立证明 tests 内 instruction 缺陷，作业员按主文第2节备证并合法修复，合同变更则独立重推/双冻结、失效并重验受影响项后送检；同样需求在 tests 外则只读记录并移交。未闭合缺陷限制对应验收，不把移交当修复 PASS。
- 合法默认本地 oracle：作业允许执行、必要性和合法隔离入口可核，无网络/秘密/答案暴露；QC 可在题包强制只读、task 外获准输出隔离的入口直接核验，或协调者编排获准运行让 QC 核隔离输出，不要求补 oracle 批准。明确静态只读则不运行。
- 仍拒绝：遍历 .pipeline、把答案发给修复方/外部 judge、改 tests 外环境/runner、越过用户明确只读或禁改、使用工具拒绝后的旁路；这些不是本次解除的授权条件。
- 历史不准入但当前全题可继续：历史修改主张所需旧 task_path 无权威恢复来源，只有当前 preimage 和 handoff 指标；不报该历史主张 PASS。记录穷尽来源及影响后继续独立当前全题 tests/报告/非写入独立 QC；无本次历史必需门、无无据沿用旧主张且当前全部必需证据通过，可当前交付/UNATTENDED_COMPLETE。若用户明确要该历史认证，仍不报原请求全范围完成。

最终分别报默认许可实际使用的角色/精确对象、tests 内实际修法与合同变更证据、外侧 instruction 需求及移交状态（外部变更单列来源）、本地 oracle 是否实际执行、准入/未准入范围和真实验证结果。不再把缺少逐题 GT/oracle 批准或 tests 内逐文件批准作为停止原因；外侧必要改动未由有权负责人完成时按实际影响移交/限制结论。事实材料灭失、明确用户限制、工具拒绝、无安全入口及未授权外部动作仍按真实影响停止。默认许可不等于材料齐全或验收 PASS。
