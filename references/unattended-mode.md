# 无人值守：独立质检、作业员返修、验证与复检

这是显式开启的执行模式，不是新作业类型、后台调度器或无限授权；按 [WorkC 作业员执行 SOP](execution-sop.md) 的通用修验流程自动执行。主 WorkC 是作业员/协调者，不是独立 QC。STANDARD 的 FULL_ACCEPTANCE 已要求独立复核，明确“直到 pass”或完成交付也须按请求范围返修复检，不必等用户说“无人值守”；UNATTENDED 增加默认完整范围、当前题外侧只读检查及无逐轮提示的自动推进，不扩大权限。默认许可与开工准入以 [qc-exceptions-and-admission.md](qc-exceptions-and-admission.md) 为统一合同：WorkC 目标明确后，相关 GT/oracle 静态 QC 及必要合法隔离本地 oracle 验证默认许可，不请求逐题批准；该许可同样适用于标准模式，并非无人值守另授。题包写集合硬锁整个 tests/** 与同一根 qa_report.md；tests/test.sh、tests/judge.py及tests内runner/shim/helper/instruction/config均可测试侧修复，不另设冻结子集或allowlist审批。tests_allowlist映射本次实际操作范围，默认tests/**+根QA，用户明示局部/只读/禁改/更窄路径限制优先；tests外除根QA只读移交，包括外侧instruction/runner，规范化真实落点在tests外的别名/链接不能写；根QA仅授权真实同根qa_report.md，不借其别名/链接扩至其他外侧目标。Skill 维护不启动实际题包；其余禁读、单点写、凭据隔离、真实验证与正式规范仍生效。用户明示只读/禁改/禁运行、更窄范围及工具权限拒绝优先，不扩普通新 candidate 或外部 judge。准入是作业员依据真实证据核查，不是用户批准；跑完步骤、子代理未发现问题、ADMITTED 或循环结束均不自动等于 PASS。

**连续执行接口**：按 [连续执行合同](continuous-execution.md) 处理全部阶段转移。获准 Docker 运行遇已安装组件停止，由作业员普通启动并有界检查就绪后续跑；缺当前运行证据则合法查源/必要重跑，不只披露未证或移交。静态 QC 的 PASS_STATIC_SCOPE 与运行复核分别记录；未闭合门还有合法下一步时继续执行，最终停止必须过该合同第4节。此规则 STANDARD 同样适用，不以无人值守为执行前提；明示只读及其他边界保持。

## 1. 触发、范围与退出

- 用户下达“无人值守模式”“开启无人值守”“无人值守执行/修复/验收”，或语义明确等价的执行指令时，设置 `execution_mode=UNATTENDED`。仅咨询“什么是无人值守”、引用这几个字、普通“直到pass”不触发。
- 不再逐轮询问是否继续。唯一当前 task 明确且无用户明示限制时，单独“无人值守”默认 FULL_ACCEPTANCE：自动完整修复、验证当前题 tests，更新同一根 qa_report.md。该执行请求即许可整个 tests/** 侧修复及根报告写入；作业员将 tests_allowlist 映射为本次实际操作范围（默认tests/**+根QA），不另设冻结子集或逐项审批。此前仅标为局部的作业标签不阻该默认；用户明确的更窄范围、路径限制、只读/不产生文件、禁改/禁运行仍优先。
- 没有当前目标时不猜题，记 `BLOCKED_MISSING_TARGET`。多题且没有选择依据时同样停止，不自行挑选。当前是 Skill 维护或纯咨询上下文而非题包作业时，仅启用模式不足以启动题包。
- 明确只做局部修复、报告或指定运行时，分别选 LOCAL_REPAIR、REPORT_QC/report-only 或 RUN_ONLY；明确只读选 READ_ONLY。默认入口包含tests内instruction、runner及config写权，不增加tests外（根QA除外）或用户明示禁改对象写权、普通新候选执行或外发授权；整个tests写权不授权秘密/GT读取或答案暴露。
- 用户说“退出/关闭无人值守模式”即切回 `STANDARD`；停止当前循环，不撤销已有合法变更。只在当前会话明确目标中保持模式，不假定跨会话持久开关。
- 不设默认轮次上限，也不设连续无进展轮数硬停。无显式预算时，尚有合法可修或补证路径就继续；不能仅因8轮或两轮未闭合停止。用户显式预算按原意记录和遵守，耗尽记 `STOPPED_BUDGET`，不是 PASS。中断不会自动后台继续，不创建定时/闲时任务。

开始时在本次验收清单记录模式、对象、tests_allowlist、同一根 qa_report.md 与写集合硬锁、tests 修复依据、tests内instruction修法/正式版本变化及tests外instruction只读需求/移交责任（有对象才列）、本次运行范围（必要合法本地 oracle 记 WORKC_DEFAULT，普通新候选/外部调用另核权限）、QC文档路径、规范采用、独立复核要求、预算及可核起始版本。另记 qc_role / qc_read_scope / qc_permission_basis=WORKC_DEFAULT / applicable_clause / obligation_freeze_ref / scoring_design_freeze_ref / actual_reads，绑定本次精确相关静态对象、先义务后设计独立双冻结及实际已读内容；精确范围是审计记录，不要求用户另批。没有某条外部条款时，明确 QC 目标可作必要性依据，不空造条款。

逐依赖范围记录 admission_status=ADMITTED / NOT_ADMITTED / N/A、admission_scope / historical_requirements / preimage_refs / future_run_plan / admission_evidence_refs / admission_owner / admission_reason；必需旧材料准入、每次 授权 tests 写前 ROUND_PREIMAGE 保全与修后验证生产条件先实际核查，再开依赖循环。future_run_plan 列必需入口/模式、本次运行范围（必要合法本地 oracle 记 WORKC_DEFAULT）、合法 evidence 来源、隔离/最小挂载、版本/依赖/服务、逐项/聚合结果位置、失败处理及责任；它不是未来 VERIFIED 结果，不要求修前已有修后结果，也不保证未来服务不会失败。只读时仅回复记录；允许写时置同一根 qa_report，不造 sidecar。

## 2. 作业员与质检子代理

内外问题处置统一按 [SKILL §2](../SKILL.md#2-先选本次作业固定验收范围)，详细登记按 [报告合同 §2](verification-and-reporting.md#2-状态归因与证据范围)。修复/交付范围内已确认的 tests 内缺陷必须由作业员实际修复、完成适用合法验证，并在同根 QA 写实际修改/结果；记录、建议、移交或让 QC 接手均不替代返修。runner/config/helper/instruction 与其他 tests 内容同等处理，不设内部保护子集；明示只读、局部、指定运行及真实证据/安全限制仍优先。

**作业员即主 WorkC/协调者**：主动查找、确认、修复并验证本次授权问题；自查和报告自查不是独立 QC，不等待 reviewer 发现全部问题，尚有合法可执行返修时不只给审计意见。所有实际修复及有依据的不改/撤回决定都进入既有 QA issue/轮次。唯一可以单点写整个 `tests/**` 与同一根 qa_report.md、集中修复并裁决问题的角色；tests_allowlist映射本次实际操作范围，默认tests/**+根QA，不另设冻结子集或allowlist审批。本次合法验证可由作业员或独立 QC 按执行合同完成；题包写集合硬锁，模式不扩权。tests/test.sh、tests/judge.py及tests内runner/shim/helper/instruction/config均可按授权正式依据修复，留preimage/diff/终态和实际验证；tests外除根QA均只读，包括外侧instruction、persona、environment、solution、Dockerfile、依赖、根manifest及runner/shim/helper，记录依据/影响/责任后移交，移交不算已修复或PASS。仅审核、READ_ONLY/CONSULT/RUN_ONLY 不变为写作业。写前核规范化实际目标；目录/glob、同名、链接或别名不能让真实tests外目标获得写权，根QA仅按单独授权。用户明示局部、只读、更窄范围或禁改优先；tests内对象不因名称或类型自动冻结。无根报告写权不改 tests，不创建 sidecar、整题副本或私造补丁产物。

**独立质检子代理**：未参与修复；子代理不写题包，但可执行安全核验；按 [质检执行合同](qc-exceptions-and-admission.md#11-质检可执行核验但题包不写) 查询现有环境、解析允许文本，并在既有作业运行许可内独立做必要隔离回归/verifier-only/本地 oracle。先核入口、import/collect 与子进程副作用，以已可用强制只读边界保护 task 全路径；缓存/日志/字节码/结果只能进获准 task 外隔离工作区，不复制题包或造补丁，不自行安装/改系统/重启服务、新候选或外发 judge。无安全入口不执行，明示静态只读/禁运行及默认静态 REPORT_QC 优先。它先从允许正式输入独立核本次义务和评分设计，再核先 obligation_freeze_ref 后 scoring_design_freeze_ref 的独立双冻结；随后依 qc_permission_basis=WORKC_DEFAULT 静态核 qc_read_scope 精确列出的相关 GT/oracle，并记录 actual_reads，不请求逐题读取批准。目标不明不猜题，未双冻结先独立推导/冻结，不能用补授权代替；答案一致不证明正式可推导或评分正确。

协调者及设计/修复角色不读 GT、不接收隐藏答案或可反推答案的原文/摘录/数值/摘要；reviewer 仅回报正式来源支持的缺陷位置、可推导性、结论及脱敏证据引用。GT/oracle 不作为义务来源、运行时评分答案依赖、候选输入或 judge evidence，不外发答案；角色名不授权向未获准模型服务发送答案。所有参与者对 .pipeline 继续禁读、禁引用、禁依赖，禁止搜索/hash/挂载及临时副本或他人结果绕过；秘密不读不转写。

静态 QC 本身不等于动态验证；本次作业允许执行、oracle 验证必要且合法隔离可行时，独立 QC 依 WORKC_DEFAULT 可默认安全隔离执行本地 oracle，或协调者编排获准运行，不请求独立 oracle 批准。先核入口版本/副作用、最小只读挂载、task 外输出与凭据隔离；QC 核隔离输出，协调者只收脱敏状态/结果引用，不获得隐藏答案。不让协调者/修复角色、普通候选或 judge 接触 GT/隐藏答案，不修改tests外或用户明示禁改的入口，不扩普通新 candidate 或外部 judge。READ_ONLY/CONSULT、用户明示禁运行、工具权限拒绝、需要未授权外部调用/秘密或确无安全隔离入口时停止对应运行，记录真实原因，不伪造证据。

作业员首阶段自查、修验及外侧只读检查记录完成后，自动用 Agent 派未参与修复的质检子代理；至少一次独立审核，QC 反馈发生返修则安排修复后的独立复检。受阻事项先准确记录，不要求其伪装完成才派 QC；其他可执行范围继续。没有变更时，初审若已核当前版本全部本次必需项可作为最终独立审核，无需空转再审。后续可恢复同一不写题包 reviewer以核受影响项；它从未写修复且始终独立判断。完整验收首次覆盖全题，局部按目标/依赖，最终核全部本次必需项。可以派多个独立核验视角，但不要求固定数量或多数投票。

首次质检必须真正读取 `E:/work-C/doc/质检SKILL/qc-qa-report/SKILL.md`，或当前请求明确指定的替代权威QC主文档。记录实际已读路径、版本/摘要或具体位置与适用条款；不得仅依协调者摘要或把文件存在当已读。适用附录逐一核采用依据，已采用才实际读并执行其门；复检核文档版本未变可引用此前读取，变化则重读。文档读不到或子代理不可用须如实停止对应独立质检门，不退化成作业员自检却宣称模式成功。

给 reviewer 范围、正式来源、task 不写边界、既有运行许可/隔离入口、当前文件版本及可访问证据索引，另给 qc_permission_basis=WORKC_DEFAULT、精确相关读取范围/适用依据、独立双冻结及准入记录，不给预设 PASS 或作业员“正确修法”作为答案。reviewer 先独立核义务和评分设计，再读实现/待证报告；核独立双冻结后才静态核相关 GT/oracle，不等待逐题批准。可以在合法范围核已有真实运行结果，也可按执行合同独立产生必要隔离核验结果；含隐藏答案的输出不能传给修复角色。执行核验不等于参与修复，不能把 QC 的动态能力用于越过作业上限。

每次 reviewer 给当前版本逐项发现及可核回执；qc_role 只填实际独立 reviewer，作业员自查另在既有 issue/轮次记实际工作，不混入 QC 角色或新增状态机。回报内容如下。

| 字段 | 内容 |
|---|---|
| 已读规范与适用性 | 路径/版本或位置、条款、采用依据、N/A或缺材料；文件存在不冒充已读 |
| QC权限与双冻结 | qc_role/qc_read_scope/qc_permission_basis=WORKC_DEFAULT/applicable_clause/obligation_freeze_ref/scoring_design_freeze_ref/actual_reads；未启用例外也说明，无隐藏答案回传 |
| 材料准入 | admission_status/admission_scope、必需旧材料 VERIFIED 或正式替代接受引用、preimage_refs、future_run_plan核查、实际依据与责任；声明检查非认证 |
| 实际核验与隔离 | 执行者、command/mode/版本、最小输入与task强制只读保护、task外隔离输出引用、预期/实际、run/freshness；未执行与具体限制；不回传隐藏答案、不写根QA |
| 技术tests结论 | 目标义务、rule/helper/parser、注册聚合、安全与双向/运行证据、范围与状态 |
| 本轮报告质量QC结论 | 核本轮新写/更新QA的事实、缺陷/修法、真实diff、运行、freshness、指标、限制及完成声明；无always-failing也审核，不N/A，绑定当前版本与证据 |
| 历史失败 A/B 归因QC结论 | history_object_status=APPLICABLE/CONFIRMED_ABSENT/UNDETERMINED，实际查源与对象映射；历史审核状态另列，适用时核反馈行、断言、可推导性、轨迹、A/B及历史修法；确认无对象才历史N/A，未知/旧证据缺失UNVERIFIED；引用验收矩阵required/authority/dependency说明是否为当前门及影响，不从对象状态推必需性 |
| 发现 | 稳定issue ID、正式位置、最小反例或证据、影响、确认缺陷/关键未决风险/建议/范围外 |
| 复检结果 | 针对当前版本的已闭合与未闭合项、证据freshness、缺口与责任 |

按 [报告双层合同](verification-and-reporting.md#7-报告与qc接口)，本轮报告质量与历史失败 A/B 是不同对象，不用“tests看起来正常”替代报告核验。本轮新写/更新QA就必须由独立reviewer核本轮质量并纳入模式成功条件，无always-failing也不能N/A；无缺陷时仍核无缺陷结论、运行及限制，不强造失败行。历史沿请求、正式映射/标记、允许artifact及QA历史查证，不能以报告自述N/A证明不存在；只有 CONFIRMED_ABSENT 才历史N/A，UNDETERMINED或旧关键证据缺失为UNVERIFIED。质量PASS可准确记录历史/技术未证，但当前关键主张自身缺证则质量UNVERIFIED，确证错误FAIL；不把两层或技术状态互相替代。权威修改前 task_path、反馈/失败身份映射或关键旧轨迹为本次必需而未 VERIFIED、也无有权负责方正式接受具体替代时，先合法查源/补取；仍缺则依赖历史 QC/返修 NOT_ADMITTED、相关结论 UNVERIFIED，不改成 N/A，不启动依赖循环。

QC 文档不自行扩大权限；目标明确的相关 GT/oracle 静态核查及必要合法隔离本地 oracle 验证按统一合同默认许可，仍遵守独立双冻结、防答案污染、准入和作业上限。题包写集合硬锁整个 tests/** 与同一根 qa_report.md（用户明示更窄限制优先），tests内instruction/runner/config可依法修复，不另设冻结子集或allowlist审批；tests外instruction及其他外侧对象除根QA仅只读移交。多报告、.pipeline、tests外（根QA除外）或用户明示禁改路径的操作仍不导入，限制相关结论而非丢弃全部合法审核部分。正式 QC 证据替代仍须有权负责方接受具体对象、版本及条款并留可核记录；解除操作批准不取消此要求，不自造历史或单方改变外部 QC 接受口径。历史对象状态、历史审核状态与当前交付必需性按 [报告合同 §7.2](verification-and-reporting.md#72-先发现对象不能用报告自证不适用) 及 [§7.2.1 历史未证只限制实际依赖的结论](verification-and-reporting.md#721-历史未证只限制实际依赖的结论) 分判。复用本次验收矩阵的 required、权威来源/版本/采用依据、对象/范围、实际依赖与缺口影响，不新增门控状态。明确历史验收请求、正式采用且适用的历史条款或当前交付主张真实依赖旧失败/旧修改，才使对应旧证据必需；完整tests验收、无人值守、模板栏或旧候选失败本身不创设通用历史门。旧修改对比核权威原task_path，旧行为归因核对应旧轨迹；当前完整 tests 修验核正式输入、本轮真实 preimage/diff/终态、真实必需运行和当前版本独立 QC，不捆绑全部遗失旧材料。非必需历史仍 UNVERIFIED，当前FULL tests、当前报告及真实独立QC的自身必需门闭合后可PASS/UNATTENDED_COMPLETE，不静默降为LOCAL。真实历史门保留来源/版本/对象、受影响主张，未闭合时不称原请求全要求完成，不用 handoff 指标、新 run、当前 preimage 换历史 PASS。当前引用错误/未证旧行须补证或有据纠正/撤回依赖，保留原行、来源与原因；不擦除或换标签逃避当前错误修法/分类，不借改范围规避真门。

## 3. 自动闭环

以下为默认完整修复路径；明示局部按本次范围裁剪，只读仅保留静态备证、自查、外侧检查、独立审核及回复，跳过全部写入和运行，RUN_ONLY 仅执行明确运行模式。通用步骤不覆盖用户上限。

1. **初始作业、备证与准入**：按 [统一合同](qc-exceptions-and-admission.md) 和 [材料准备](evidence-preparation.md) 完成先义务后评分设计的独立双冻结、逐项证据需求、评分身份台账、起始版本及预检。必需旧 task_path、反馈/失败身份映射与历史轨迹先合法查源、核正式映射、获准补取，可恢复先取；实际 VERIFIED 或有权负责方正式接受具体替代才准入依赖返修/历史 QC。用户明示限制、工具拒绝或补取需未授权范围外动作时列具体阻止，确已穷尽记 EXHAUSTED/NOT_ADMITTED，不启动依赖循环。reviewer 可先核材料准入，不将其称历史 QC PASS。每次 授权 tests 写前先合法保全各目标原内容/preimage（原不存在记 ABSENT），无根报告写权/合法保全不写。本轮漏保全、漏登记或漏做当前必需验证均是WorkC生产缺口，合法查源/补登记/补验并限制未证主张，不倒填preimage、伪称当时已登记或推给旧历史；当前preimage不自动成为权威原题，无旧轨迹只记主动发现/真实探针，不编Agent行为。修前核 future_run_plan 的本次运行范围（必要合法本地 oracle 记 WORKC_DEFAULT）、入口、隔离及证据可生产条件，可在本次范围合法修复的 tests 内验证入口缺陷先留证修复并验证，不当作外部环境阻塞或据此拒绝依赖返修；真正超出写/运行权限、证据或安全条件且无法合法产出必需验证时，才停止受影响范围。不要求已有修后结果，准入不是用户批准。原累计缺失可另立接手阶段指标，不反推旧 N0，也不替代历史准入；当前独立局部或完整tests范围可单列准入而保留真实历史门，旧缺口不自动升为当前全局门，必需性按 §7.2.1 核。
2. **作业员先自查修验**：完整入口先读并执行 [全题逐项技术清单](pre-delivery-qa-fusion.md)，从正式输入核全部义务及确定性/语义判据（含未改项）、helper/parser、证据控制权、独立复算、真实输入对拍和注册聚合；逐项留适用轴、预期/实际、run/版本与已实测/适用总数，不能仅追反馈/风险。明示局部/只读依本次范围裁剪，确认缺陷后按下方修复与真实验证要求集中修复、补正反例、执行适用正式验证，更新同一根 QA。没有发现不硬改；缺历史仅暂停依赖历史的事项，不阻无关可验证修复。备证、准入和双冻结由作业员内部自动处理，不逐项请求用户批准。历史查源已EXHAUSTED且无新来源、权限或相关版本/依赖变化时，引用其精确来源/结果/对象/主张/门控影响/责任记录，不每轮重查；继续当前FULL修验及独立QC，不以非必需历史UNVERIFIED循环空转或停止当前交付。
3. **tests 外只读检查并记录**：默认检查当前 task 与 tests 正确性有关的允许正式材料，如 instruction、persona、policy、fixtures、schema、环境及资源合同；不递归整个工作区、不读 .pipeline/秘密，不把业务实现作为修复任务，不让作业员读取 GT 或隐藏答案。记录检查对象、版本/位置及结果；有问题直接按精确路径、实际证据、对评分/验证的影响、责任方和移交状态写同一根 qa_report.md，不改外侧、不等待外部先修、不将全部外侧缺陷变成交付门；只有实际依赖的必需项限制对应结论。未发现也记范围，不能宣称未检查部分无问题。tests外instruction仅只读移交；tests内instruction缺陷归入授权tests修验，不因instruction类型冻结；无关缺陷或建议不阻 tests 闭环，真影响必需判据的外部问题限制对应结论，记录不是修复。
4. **独立质检**：派发前先完成回顾登记，按 [回顾登记](verification-and-reporting.md#731-回顾登记先对账不能把漏写当灭失) 对照本次及相关既有发现/反馈、实际变更、不改/撤回决定、验证与 QA issue/轮次，补有可核证据的漏项并标事后登记时间/来源，不把报告未写当历史灭失、不凭回忆补造、不倒填preimage、不重复计F/A；无漏项简记范围。明示只读仅回复，局部按目标/依赖，返修后仅核新增/受影响项。首阶段完成或受阻情况准确入 QA 后，派独立不写题包 reviewer 实际阅读 QC 文档，审核当前 task 的技术 tests、本轮报告质量、适用历史失败 A/B及外侧检查/移交记录，将发现绑定当前版本与证据，完整入口同时核逐判据技术清单、覆盖分母和未验证项，不能只复核作业员声称修好的反馈；先独立核正式义务/评分设计并核双冻结，再依 qc_permission_basis=WORKC_DEFAULT 静态核精确相关 GT/oracle，记录适用依据与 actual_reads，不请求逐题批准、不回传隐藏答案。历史依赖尚不准入就核其材料及状态，不冒充历史 QC 通过。
5. **作业员核实并处置反馈**：逐项回到正式来源与实现核实，必要时获准隔离复现。按 [反馈处置](verification-and-reporting.md#2-状态归因与证据范围) 区分：确认授权 tests/报告错误实际修复而非只记录；候选真错且规则有效则有据不改、不放宽；未证沿合法路径补证、不造事实；建议不门控；冻结外侧问题只读记录移交并限制受影响门。确认缺陷按根因合并，修法从正式输入独立推出，不按 GT 改期望到一致；未复现但有实质依据的核心风险保持 UNRESOLVED。全部修复及有据不改进入既有 issue/轮次，不能凭投票、子代理 PASS 字样、自签或最终绿灯裁决。
6. **反馈返修**：再次核受影响准入及每目标 preimage，在本次实际操作范围内集中修改整个授权tests/**与同根qa_report.md；tests_allowlist默认tests/**+根QA，明示局部/只读/更窄路径限制优先，不另设冻结子集或审批。同步稳定反馈映射、实际diff与终态，写集合硬锁。tests内instruction/runner/shim/helper/config缺陷按授权正式依据实际修复、留证并验证；tests外instruction及其他外侧对象除根QA只读记录依据/影响/责任后移交，移交不算已修复或PASS。合法变更tests内正式instruction或外部有权负责人变更tests外instruction、导致正式合同变化后，记录授权正式来源、版本前后、写前preimage及实际diff；旧相关义务/评分设计与运行证据标STALE，由未接触隐藏答案的设计角色从授权正式来源独立重推并双冻结受影响范围，重核tests、注册聚合及候选可见载体并真实重验。已接答案reviewer不承担此设计角色，随后按新冻结独立复检；不按GT污染修法、不以新instruction追认旧candidate失败或放宽仍有效义务。有效A类不放宽，不能删有效规则、降门、改tests外或用户明示禁改路径或用关键词替代语义取得PASS。范围外项精确移交，不让reviewer写补丁；授权范围内也始终由协调者单点写。
7. **真实验证**：只改报告归因且规则、实际 evidence 与技术结论未变时，核原运行仍适用且 FRESH，复用有效证据并复检报告，不为改文字空跑 verifier；影响评分逻辑、证据或技术结论时，按已核 future_run_plan 实际取得正式 CURRENT_RUN，执行受影响正反例、共享依赖、注册聚合及适用正式 verifier/实际必需 judge/已采用门，核身份、真实消费、逐项/聚合、degraded 与 FRESH。计划、预检或 ADMITTED 不代替真实结果；运行失败或服务变化重新评估准入，停止受影响完成声明，保留已证范围。本次作业允许执行、必要且合法隔离可行的本地 oracle 可由独立 QC 依 WORKC_DEFAULT 执行，或协调者编排获准运行；QC 按执行合同保护题包不写并核隔离输出，协调者仅收脱敏状态/结果引用；用户明示禁运行、工具拒绝或无安全入口则停止对应运行。普通新候选/外部服务缺对应权限仍不调用，不由默认 oracle 许可扩权；QC 安全核验不扩本次运行范围，两个重评分不是两个 attempt。返修只失效依赖变化的旧证据，合法tests内正式instruction变更或外部有权负责人变更tests外instruction、导致合同变化后须独立重推/双冻结、失效受影响证据并真实重验，完整验收覆盖全题必需项。
8. **更新并复检**：先回顾登记新增/受影响发现、变更和验证，核遗漏并同步实质报告和计数，再给独立reviewer当前版本/变更范围及真实证据进行复检。若最终修改报告归因、规则或证据，重核受影响结论；最终只追加准确引用reviewer结果的审计记录，不无限自指“报告新增记录后又全量重审”。
9. **判定并继续**：本次适用门闭合则成功；未通过且尚有合法可修或补证路径，就回到裁决、返修、验证、更新 QA、独立复检，无需用户催促，不要求每轮立即闭合一个 issue 才继续。重复同一无效动作时重新查证根因、证据或合法修法，不刷轮数；确实无法继续则列依据和责任，停止受影响部分。首阶段不每轮重启，未变且有效证据复用。显式轮次预算计入最终复检，预算内未完成仍如实收口。

已合法进入UNATTENDED的READ_ONLY/RUN_ONLY仍遵守作业上限：自动安排相关独立审核，不出现未授权修复写入；该范围审查完成不叫修复闭环或完整验收PASS。只读可报“静态审查完成，发现未解决问题”，不因审查完成报技术 PASS 或 UNATTENDED_COMPLETE。纯咨询不启用题包无人值守循环。

## 4. 成功与停止条件

`UNATTENDED_COMPLETE` 只在本次全部必需项有有效新鲜证据、独立reviewer对当前版本复核完成、无未解决确认缺陷或影响核心正确性的未决风险、本轮有报告写入时其质量QC独立核实通过、适用且纳入清单的历史A/B门闭合时成立。FULL_ACCEPTANCE 才可报整题技术 PASS；默认完整入口也必须实际完成全部必需门，不能只按作业名报通过。tests 侧通过、报告 QC 与整题外部阻塞分别报告；外侧建议或无关瑕疵不影响 tests 通过，真正影响必需判据的外部问题未解决则不能报整题 PASS 或全部 UNATTENDED_COMPLETE。局部只报局部完成/PASS。仅确认无历史对象记历史N/A，本轮报告仍审；未知/缺证保持历史UNVERIFIED，不自证当前必需门。按 §7.2/§7.2.1 和验收矩阵required/authority/dependency，非必需历史UNVERIFIED可与当前FULL tests交付PASS及UNATTENDED_COMPLETE并列，前提是当前tests、报告质量和真实独立QC的自身必需门实际闭合；不静默降为LOCAL，不断言未知旧行为/旧修改已通过。明确历史验收请求、正式采用且适用的历史条款或真实依赖主张形成的门仍须闭合，未闭合不称原请求全要求完成，不删真门，也不抹掉独立已证技术结论。外部平台/人工无真实回执不代签。子代理结论只是审核证据，作业员对清单负责。

| 停止原因 | 判定及结果 |
|---|---|
| 目标/正式对象事实缺口 | 缺明确题、正式映射不能定位instruction对象、对象/版本/作用不可核或规范化实际目标不属本次写范围；停止受影响动作，列准确事实/范围缺口，保留已证范围，不要求补逐题GT/oracle批准；tests内instruction可按授权修验，tests外instruction只读移交 |
| 用户限制/工具拒绝/范围外动作 | 用户明示只读/禁改/禁运行、更窄范围、工具权限拒绝，或需未获许可的普通新候选/外部judge/外发、tests外（根QA除外）或用户明示禁改路径操作；停止对应动作，不以默认许可绕过 |
| 安全或范围冲突 | .pipeline/秘密/答案暴露、本轮越界、无合法 oracle 隔离入口、需改tests外或用户明示禁改入口，或把整个tests写权/默认许可扩成秘密或GT读取、普通候选/外部judge/答案外发；停止核实/移交，不擅删未知文件 |
| 必需旧材料不准入 | 先合法查源/补取，可恢复先恢复；对应旧证据必需且未VERIFIED、也无正式接受具体替代时，仅不启动依赖它的历史认证/返修。确已穷尽才记EXHAUSTED/依赖范围NOT_ADMITTED，逐项列精确来源/版本、实际动作/结果、缺失对象、受限主张、required/authority/dependency与门控影响、责任及恢复条件；权限不足另记具体阻止，不将未查写穷尽。无新来源、权限或相关版本/依赖变化，不每轮重复查同一已穷尽历史，继续当前完整修复、真实验证、当前QA及独立QC。非必需历史UNVERIFIED不阻当前FULL范围/模式完成，不降为LOCAL；真历史门仍保留，未闭合不称原请求全要求完成，不用handoff指标或新run消掉真门 |
| 写前保全或运行生产条件不满足 | 无合法授权 tests preimage 或根报告写权不写目标；可合法修复的 tests 内验证入口缺陷先留证修复并验证，不冒称外部环境阻塞。确有权限、证据或安全限制致必需证据无法合法产出时只停受影响范围；未来结果未存在本身不是修前缺口 |
| 必需运行证据/服务不可得 | 按授权合法补证，修后实际运行失败或服务变化重评准入；列动作/结果、剩余路径/阶段/责任，区分 NOT_RUN、UNVERIFIED 和 BLOCKED，不一句“缺材料”结束或无限重试，计划不能替真实结果 |
| Docker 等已安装组件未启动 | 不是直接停止理由；作业员按连续执行合同核目标、普通启动、有界探测并续跑。只有具体证据证明启动/后端/权限等剩余合法路径不可行，才限制相应必需运行；不得把启动成功写成验收成功 |
| 独立QC能力缺失 | 无子代理工具或QC主文档不可读；不可宣称独立QC闭合 |
| 真实无法继续 | 经合法查证/复现后，无剩余合法可执行修复或补证路径，或继续确需外部有权负责人处理；记 `STOPPED_BLOCKED`，列具体依据、已尝试动作及恢复责任。仅轮数或暂未闭合不足以判停 |
| 用户显式预算耗尽 | 仅用户明确预算到达时记 `STOPPED_BUDGET`；无预算不设默认计数硬停，耗尽不是 PASS |
| 用户退出/中断 | 记 `STOPPED_USER` 或实际中断，保留最后完成轮次；不伪称后续已跑 |

“进展”是确证issue闭合、有验证支持的缺口消除或有效新证据，不是改措辞、重复同一命令/模型请求、降门或增加建议数。新证据可推翻旧PASS并重开该项；记录原因，不为避免无进展而刷版本。tests外环境或用户明示禁改对象的移交项立即停止该项无效重试；tests内环境配置/runner等缺陷仍按授权修验，其他独立可执行范围可继续；实际本次必需门受影响时不能称全部无人值守完成，非当前必需的历史未证不据此普遍阻模式完成。

每轮在根报告条件模块和轮次中记录 round/reviewer 已读规范、qc_role/qc_read_scope/qc_permission_basis=WORKC_DEFAULT/applicable_clause/actual_reads 与独立双冻结引用、admission_status/admission_scope 及实际准入证据、各授权 tests preimage、tests 修复依据及实际 diff、tests内instruction修法/正式版本变化与tests外instruction只读需求/移交状态及外部变更来源（有对象才列）、future_run_plan 与修后真实结果、目标版本、发现/裁决、失效与复用证据、F/A增量、未闭合门、进展、tests 外只读检查对象/结果及移交、真实阻塞依据；仅有用户显式预算时记剩余预算。checker 的声明完整性、checklist_ready 或指标可算不认证准入/QC。只读时不落盘。中断接续核最后完成轮、版本、新鲜度及当前准入；复用真实完成工作，不重复计 F/A 或伪造 reviewer/运行回执。

## 5. 最终回复示例与模式边界

触发例：已有唯一明确当前 task 时，用户说 `无人值守`，即默认完整 tests 侧自查修验、外侧只读检查记 QA、独立 QC 和反馈返修复检。也可明确指定 `无人值守 E:/work-C/<task>，仅本地 verifier-only，不启动候选或外部 judge。`，无需再追加逐项 tests/根报告批准。

若实际必需judge缺外发授权：完成可合法范围，准确报停止/未完成，不按例子授权调用。若用户只说 `无人值守模式，静态只读质检，不产生文件`：作业员仅做静态备证、自查和外侧只读检查，再自动派只读 reviewer；结果仅在回复记录，不修复、不执行题包、不写报告。

成功回复：按实际范围报告本次局部修复或当前FULL tests完整验收已完成，不为非必需历史未证把FULL降为LOCAL；仅自身必需门真实闭合才PASS/UNATTENDED_COMPLETE。列独立QC文档、qc_permission_basis=WORKC_DEFAULT的实际角色/精确读取范围/双冻结引用、实际准入范围、tests内instruction修验及正式版本变化、tests外instruction只读需求/移交状态（合法变更单列授权来源）、本地oracle是否实际执行及隔离结果引用、复检范围、真实run、本轮报告质量QC状态及独立依据。历史另列history_object_status、历史A/B状态及查源依据（仅CONFIRMED_ABSENT才N/A），引用矩阵required/authority/dependency及缺口影响，不将UNVERIFIED假签历史PASS。原请求有未闭合明确历史门时，即使当前技术部分已证也不得称原请求全要求完成。原题/接手阶段指标及未请求外部阶段如实分列。

停止或未开工回复：本次依赖作业 NOT_ADMITTED，或无人值守循环因具体原因停止；列准入与未准入范围、查源/补证动作及结果、已验证补丁、未闭合必需项/精确状态、tests内instruction修验及正式版本变化、tests外instruction只读需求/移交状态（合法变更单列授权来源）、最后有效轮次与证据、恢复/补验责任。单列当前独立局部或完整tests完成时保留真实旧门及历史UNVERIFIED；无可证当前历史必需门时不阻该范围/模式完成，不用阶段指标替历史准入，不使用无范围的“全部PASS”。停止原因须为真实目标/正式对象事实缺口、材料缺口、用户明示限制、工具拒绝、安全入口或范围外动作，不再列“实际题缺 GT/oracle 单独授权”；tests内instruction属于授权tests修验，tests外instruction仅只读移交，用户明示禁改优先；未闭合问题按实际影响限制结论；默认许可不等于准入或 PASS。

这个模式由当前会话的作业员通过 Agent 及获准工具执行，不保证客户端跨会话自动触发、宿主权限提示被绕过、后台常驻或模型服务永不失败。用户未明确要求“使用workflow/用工作流”作为手段时，不创建动态workflow；明确要求该手段则遵循其工具要求，仍保留同样边界。
