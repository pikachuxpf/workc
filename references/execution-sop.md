# WorkC 作业员执行 SOP

这是现行内部执行步骤，不是外部规范的采用证明。修复、交付及无人值守时，**主代理是作业员，不是独立质检员**：负责主动找出并修好授权 tests 的真实错误，做验证、写同根 QA、落实质检反馈。自查属于生产过程，不签独立 QC PASS。独立质检是未参与修复、不写 task 的子代理；它审当前交付并给证据化反馈，可在既有作业许可及安全隔离下独立核验，不能替作业员实施修复。

写范围以 [主文第2节](../SKILL.md#2-先选本次作业固定验收范围) 为准：作业员单点修当前题 tests/** 全部内容与同根 qa_report.md，用户明示限制优先；tests 外除 QA 全部只读移交，tests 内 instruction/入口等无路径特冻。安全与准入按 [统一合同](qc-exceptions-and-admission.md)。QC 对 task 全路径含缓存/日志/结果不写；其动态核验依 [执行合同](qc-exceptions-and-admission.md#11-质检可执行核验但题包不写)。GT/oracle 双冻结、答案隔离、.pipeline/秘密禁区、候选/外发权限不变。步骤不会扩权、创设阈值或取消正式必需门。

**内外处置总则**：修复/交付中，tests 内本次范围已确认的问题必须实际修复、完成适用合法验证、将修法与结果记同根 QA，不以只登记/建议/移交结案；tests 外除同根 QA 不改，相关允许材料的问题直接记同根 QA。实际目标决定归属，内部可修的 runner/配置故障也回修复流程，不直接推成外部环境阻塞。明确只读/局部/指定运行等上限仍优先；真实权限、保全或安全/执行阻止须有具体证据。外侧问题只有实际影响本次必需门才限制对应结论，不能一律等外侧修好才交付；内部确认缺陷未修或必需验证未闭合不能该范围 PASS。

**连续推进总则**：本 SOP 必须结合 [连续执行合同](continuous-execution.md) 读完再开工。阶段产物不是停止点；每步完成即进入下一适用步骤，遇故障执行恢复分支，向用户汇报进度后继续，无需用户催“继续”。普通已安装组件的启动由作业员处理，不把 Docker 未启动当作外侧文件冻结问题移交。最终发回复前必须过连续执行合同第4节停止闸门。

## 1. 接单：确定对象和本次职责

**输入**：用户请求、明确当前 task、正式版本与采用依据。按 [路由](routing-and-authority.md) 选作业和最小充分范围。

- LOCAL_REPAIR：作业员修目标及实际依赖，相关验证和 QA 闭合；不自动全题巡检或增加全题独立门。
- FULL_ACCEPTANCE：作业员完整修验全题 tests，独立质检技术交付与本轮 QA；不能只复核反馈项。
- 唯一当前 task、无明示限制的“无人值守”：默认 FULL_ACCEPTANCE 及当前题 tests/** 全部内容/同根 QA 写许可，自动连续闭环，不逐轮等用户催促。
- CONSULT：只给评估，不启动题包取证/修复。READ_ONLY：静态审核，不写不跑。REPORT_QC：按指定报告范围审核，默认静态，修报告/tests另核实际授权。RUN_ONLY：只跑指定模式，报告依实际写许可。这些明确请求优先，不因 SOP 转成修复。

**产物**：复用本次验收清单，固定目标、tests_allowlist 实际范围映射（默认 tests/** + QA，仅按用户明示限制裁剪）、根 QA 写权、运行范围、必需验证/质检与通过条件；历史门另写明确请求/正式采用条款或当前结论的实质依赖，不因模板或历史状态自动增加。按 [历史分流](verification-and-reporting.md#72-先发现对象不能用报告自证不适用) 区分对象、审核状态和本次必需性，不增加第二套角色台账。只读时仅回复。

**转移**：修复/交付进入第2步；裁剪作业只做已请求且获准步骤。目标不明不猜题，Skill 维护不启动实题。

## 2. 定依据、备证和核入口

**动作**：先从允许正式 instruction/persona/policy/fixtures/schema 等独立推导本次义务，再独立固定评分设计与聚合，形成同范围/版本的双冻结；不拿 tests、旧 QA 或隐藏答案定义真值。同版有效冻结可重核复用，不每轮重设计。

按 [材料准备](evidence-preparation.md) 核本次实际主张依赖：当前规则正确性与本轮修法用正式输入、可信 preimage、实际 diff/终态及当前验证证明；历史修改对照依权威原task_path，旧候选行为归因依相应旧轨迹/产物，不把两类旧材料捆绑为所有当前修复的前置条件。每个 tests 写目标都先合法保全本轮原内容/完整修改单元，原不存在记 ABSENT；修前核 future_run_plan 的真实入口、权限、隔离/服务、证据生产位置，不要求已有修后结果。沿允许可信来源有限补证，缺历史不阻独立当前全题修复，但不删确有依据的必需历史门或造证。

实际有 judge 且本次获准运行时，预检先按 [judge-chain §2](judge-chain.md#2-配置模型与真实调用预检) 核正式配置来源、既有 `~/.agents/skills/workc/.secrets/judge.env` 引用及隔离，不因忘记位置把可用配置报成缺失。仅核存在性/脱敏状态，Agent 不读秘密值；无 judge 或未获准调用时不启动服务调用，配置存在不扩授权。

**产物**：在唯一根 QA 引用冻结、准入、preimage 和计划；没有根 QA 写权或合法保全，不写对应 tests。计划/准入不是已运行或 PASS。

**转移**：可准入目标进入第3步；真不可恢复或无合法验证生产路径的依赖项准确标未准入/未证及责任，继续其他独立范围，包含不依赖旧材料的当前全题。历史查源穷尽时固定缺失主张/对象/材料、来源/实际动作/结果、必需性/影响及恢复责任；没有新来源、权限或版本变化，不每轮重查已穷尽来源。禁区/秘密不查，不建 .bak/整题副本或 sidecar。

## 3. 主动发现并落实 tests 修复

**动作**：按 [逐项技术清单](pre-delivery-qa-fusion.md) 从正式义务对照实现。完整范围覆盖所有实际确定性/语义判据和未改项；局部覆盖目标、共享依赖、注册聚合及安全影响。检查规则/解析器/helper、证据控制权、独立复算、合法等价与违规反例、真实样本解析、实际加载与聚合，不只找格式错误。

发现问题先核正式依据、实际断言、最小反例与根因。**确认且在授权范围内的 tests 缺陷要实际修复，不只登记、建议修改或等待 QC。** 修复从获准正式输入推出，不为让候选满分放宽有效规则，不据 GT 调期望。tests 内 runner/judge/helper/test.sh/配置及 instruction 等均按主文第2节范围实际修复，不另设逐文件审批；正式 instruction 合同变更沿该节备证/登记、受影响证据 STALE、未接触隐藏答案角色重推双冻结及适用重验接口，再送独立 QC，不追认旧候选违规。有依据零缺陷不强造修改。

**产物**：稳定 issue 与实际授权文件/diff/终态；保留正反例回归和相关身份/权重变更。候选真实违反有效规则则不改，记证据和不改依据；未决风险查证而不先伪报已修。

**转移**：改动或待核行为进入第4步；发现 tests 外问题先按第5步只读记移交，不能越界修改外侧业务/环境/instruction，也不承接业务实现。

## 4. 验证本轮修法，失败继续修

**动作**：在获准合法隔离入口执行受影响正反例、共享依赖、注册聚合和适用正式 verifier/必需 judge/已采用门，按 [运行验收](runtime-acceptance.md) 核真实消费、身份、逐项/聚合、degraded 和版本。真实输入兼容不能用自产 fixture 代证；未跑就是 NOT_RUN。QC 自己的检查不免除作业员生产必需验证的责任，双方可复用已核充分 FRESH 证据而非重复跑。

**产物**：实际预期/结果、command/mode/版本、run/证据及 freshness；修法未验不写 FIXED+FRESH，不提前计 F。同根因去重、评分身份与指标按 [报告合同](verification-and-reporting.md) 复算。

**转移**：tests 逻辑失败或 tests 内可修的 runner/helper/配置/验证入口故障回第3步实际修复，再回本步验证；不能只登记成环境移交。基础设施/证据问题先核实际归属：已安装环境未就绪先按连续执行合同第2节自主恢复、重做就绪预检并回本步；确需修改外侧冻结文件的故障才按第5步记同根 QA、不修改。缺证按运行验收 §4.1 合法补证/必要重跑并重核入口；只有具体证据证明无法合法继续才停受影响动作，不冒充候选错。尚有合法路径就继续。技术依赖实质变化只失效相关证据；技术未变且证据充分，仅报告归因修订不空跑 verifier。

## 5. 外侧检查、报告和回顾登记

**动作**：无人值守默认检查当前 task tests 外相关允许正式材料；标准修复/交付按实际依赖和请求，不把局部升级成整题外侧巡检。不扫整个工作区，不让作业员读 GT/oracle 隐藏答案或 .pipeline/秘密。

tests 外相关允许材料的错误直接在同根 QA 记精确对象、版本/依据、实际观察、对评分/验收的影响、责任与移交；外侧冻结对象不改，移交不等于已修。不影响本次必需门的外侧真实缺陷或建议都不阻 tests 交付，不等待外侧修复；通过所需的外部矛盾仍限制对应结论，写明所依赖的具体门，不把所有外侧问题升级为门。已检查无发现也简记范围，未查部分不声称无问题。

把主动发现、反馈、实际修法/diff、不改决定、验证/run/freshness、指标和外侧问题写同根 QA，分别列本轮质量与适用历史 A/B。送检前按 [回顾登记](verification-and-reporting.md#731-回顾登记先对账不能把漏写当灭失) 对账可见真实工作与 issue/轮次，补有证据漏项，标事后来源，不倒填保全、不造历史、不重复 F/A；返修只核新增/受影响项。报告自查是作业员责任，不是独立质检。

**产物**：当前实质 QA 与证据索引；准确区分已修、待验、不改、移交及未证，不只写“未通过”。历史限制必须写具体未证主张/对象/缺件、已查结果和本次门依据/影响，不能只留“旧候选失败 A/B：UNVERIFIED”。旧报告不受支持的归因或修法须核实/明确纠正并保留原引用和理由，当前错误修法仍返修，本轮漏保全/登记仍是生产缺口，不靠删行或改审查标签解锁交付。

**转移**：本次需独立质检进入第6步；标准局部不需额外独立门时按本次清单进入第8步，不强加全题 QC。

## 6. 送交真正的独立质检

**动作**：用 Agent 派未参与修复的独立 QC，或恢复仍独立的 reviewer；完整验收及无人值守有本轮 QA 写入必须独立审。给目标范围、当前正式/实现/报告版本、冻结/准入及可访问证据索引、已核运行许可/隔离边界，不给预设 PASS 或把作业员结论当答案。

质检实际读取 `E:/work-C/doc/质检SKILL/qc-qa-report/SKILL.md` 或本次指定的权威替代主文，记录路径/版本/适用条款；已采用附录才读并执行，不能只采信作业员摘要。按本次对象核 tests、QA 实质主张、适用历史行及外侧记录，不用内部质量 PASS 代外部条款通过。双冻结后相关 GT/oracle 可按既有默认许可核；任何隐藏输出不回传作业员。需要实测时按安全执行合同，不能写 task。

**产物**：独立回执绑定当前版本与已读规范；逐项给问题ID、精确位置、正式依据/可推导性、反例或证据、影响范围、结论及未证原因，回复而不写 task。自查、模型投票、结构checker通过不是该回执。

**证据模式分流**：按 [质检入口交接](continuous-execution.md#3-质检入口与证据必须匹配) 核实际主文边界。现行 qc-qa-report 只审静态材料，不运行或读取轨迹/运行结果；其回执最多认证对应静态范围。完整交付的真实运行由作业员生产，另交已采用含轨迹入口或明确的 WorkC 独立运行复核；不把通用 QC 可执行能力塞进 strict_static 入口，也不把缺外部入口默认为内部替代已获认可。

**转移**：回执的问题/缺证进入第7步；无本次必需未闭合项且当前版本实际核通过进入第8步。工具/主文不可用如实限制独立门，不让作业员改名冒充质检员。

### 6.1 首轮完整审核与集中反馈

作业员首次送检按主文 §4.1 提供完整材料包；reviewer 以正式义务和实际评分身份为库存，完成本次范围全部适用项，不能发现第一条错误就停止剩余可审范围。完整验收含未修改判据及共享依赖；局部/报告审核仍限本次对象。strict_static 只交静态覆盖，运行范围另走合法入口，不为凑完整越界。

回执复用既有逐规则表与 issue 引用，交代应审库存、已审身份、未审/未证身份及原因；按独立根因集中列全部已确认发现，给关联载体、判据、最小反例/证据及影响。总体 FAIL 与审核覆盖是否完成分别说明；有一项 FAIL 不代表剩余都已审。可先发阻止危险动作的即时提醒，但它不是最终整轮回执；真实权限/材料/预算阻止时明确中断范围，不承诺永远不会再发现问题。

作业员按根因制定一次修复批次，沿共享 helper/parser、正常/失败分支、实际载体与注册聚合追受影响范围，核适用合法等价及违规反例，再统一修验、更新 QA、送复检。仅为共用文件而根因不同的问题不强合并，同一根因不按路径或轮次重复计 F。

## 7. 核实反馈，作业员返修，再送检

| 反馈事实 | 作业员落实动作 | 返回位置 |
|---|---|---|
| 确认授权 tests 错误 | 核 preimage，实际修 tests，更新正式可推导修法与证据 | 第3–5步，随后第6步复检 |
| QA 缺项、归因/状态或修法叙述错误 | 核真实工作/证据并修 QA，保留旧结论纠正原因；不能仅改标签救 PASS | 第5步及第6步受影响报告复检 |
| 关键主张缺证或运行证据失效 | 沿合法来源恢复/补适用验证，未证不称修好；新 run 不证过去 | 第2/4–5步及第6步 |
| 有效测试正确、候选真错 | 不放宽规则，记录正式依据、实际行为和不改理由；交 QC 核实分歧 | 第5–6步 |
| 未复现风险/无依据猜测或建议 | 针对性查证；有实质依据风险留未决，建议不新增门，不盲改 | 第3/5–6步相关项 |
| tests 内可修的 runner/配置/验证入口错误 | 按 tests 缺陷实际修复、适用验证和 QA，不只记录环境移交 | 第3–5步，随后第6步复检 |
| tests 外相关允许材料错误 | 直接记同根 QA 的位置/证据/影响/责任，不改外侧；无必需依赖不等外侧修好，有依赖仅限制对应结论 | 第5步，继续其他独立可执行项 |
| 真实权限、证据保全或安全/执行条件阻止 | 记录具体动作/结果、阻止依据及受影响必需门；不能靠只记阻塞跳过内部可修问题 | 第2/4–5步，确无合法路径按第8步受阻收口 |

修复及报告只能由作业员集中写，QC 不生成/应用补丁。反馈不是投票裁决：回正式来源和实际实现核实；不同意须有可核证据并交相应复检，不单方面删门/驳回后宣布通过。

完整交付、明确“直到 pass”或无人值守任务，**未通过且仍有合法可修/补证路径时继续返修送检，不以输出一份 FAIL 清单结束**。标准模式不是免返修，UNATTENDED 是自动执行策略而非唯一允许闭环的模式；明确局部只循环请求范围，不加全题独立门。独立复检绑定修后当前版本和受影响项，未变有效证据可复用，不每轮重新跑全题或重读全部历史。最后仅追加准确引用回执的审计记录不无限自指复审，实质改报告/规则/证据则仍复核对应结论。

### 7.1 复检新问题归属与影响范围

复检发现新问题时，reviewer 给正式依据、旧/新版本及反例或证据；作业员核实后在既有 issue/轮次补归属，不另建审批台账：

| 归属 | 判断与处置 |
|---|---|
| 首轮漏检 | 旧版已存在，且在首轮范围、材料可得。补原覆盖缺口，沿同一漏检原因检查相关判据；不能伪称返修引入。 |
| 返修引入 | 可信前后版本证明本次改动引入回归。修复并补覆盖受影响依赖的回归；本轮引入又修掉不计基线 F。 |
| 新证据发现 | 新获准样本、反例或运行事实使原结论可被推翻。说明新增证据及旧证据为何不足，重开相应项，按真实影响扩大复核。仅换 reviewer 不等于有新证据。 |
| 新增要求 | 引用本次新增用户要求或正式合同变更的权威来源、版本、采用依据和适用范围；确已生效则更新矩阵及失效范围。仅个人偏好、建议或未采用条款不能变为打回门。 |

若现有材料还无法区分漏检和返修引入，记“归属待证”及缺少的前后证据，先核实处理真实缺陷，不编造责任或为分类停工；取得证据后补分类。问题是否成立与发现归属分别判断：真实范围内缺陷仍要修，不能以“上轮未提”拒修；无依据新增要求也不能借“新问题”强加。

复检输入为当前正式/实现/报告版本、稳定 issue 对照、实际 diff、受影响依赖、补验结果和可复用 FRESH 引用。reviewer 核已修项、关联正反例及连带影响；共享加载、权重/聚合、正式合同或证据权限变化时按依赖扩大，不只看改动行。不受影响且版本兼容的有效证据复用；纯报告归因变更重核报告，不空跑技术链。完整交付最终仍须有覆盖当前全题所有必需项的兼容证据，不能把未审项算复用，也不能为省轮次封口真实新反例。

## 8. 通过或真实受阻收口

本次 PASS 要同时满足请求范围的必需修复/验证门、本轮报告要求，以及实际要求的独立质检对当前版本通过；独立质检通过以真实回执为据，作业员不能自己签它。局部只报局部，完整技术验收实际覆盖全题，候选分数/历史 QC/报告质量/外部阶段分别报，不混一项总标签。完整交付或无人值守还有必需未闭合项不能报完成；无关建议/外侧问题不扩大本次门。历史 UNVERIFIED 不自动阻断当前交付：本次无必需历史认证且当前全题修验、报告质量与独立质检均通过，可报当前 tests 侧完整交付 PASS 或 UNATTENDED_COMPLETE，另列历史未证/本次未请求及其依据，不声称历史或外部签收通过、不降成局部交付。若明确必需历史门仍缺证，当前全题可单列通过，但含历史验收的原请求未完成。

合法路径尚存就回第7步；只有真无合法路径、用户停止或显式预算耗尽才停对应范围。列具体已做动作/结果、未完成门、阻止依据、已证独立范围和恢复/补验责任；准确“已记录/已移交/待验证”不是 PASS。没有默认8轮或连续2轮无进展硬停，重复无效动作改查证/归因/修法，不刷次数。不能为到 PASS 删除有效判据、造证、读禁区、改冻结对象或扩候选/外发权限。

收口前逐行过 [停止闸门](continuous-execution.md#4-最终回复前的停止闸门)：还有可启动的已安装环境、可修 tests 入口、可生产的新鲜运行证据或可执行的独立复检，就返回相应步骤。报告 QC 认可了“技术未完成”只证明披露准确，不解除原请求的技术门；不得以修改 QA 标签、临时改局部范围或仅发待办结束可继续的作业。

最终回复先回答本次修复/交付结果，再简列实际修了哪些、不改与外侧移交、验证/run、本轮报告质量/适用历史审核及独立回执、指标/真实阻塞。未进行的人工/平台阶段不代签，发布/提交另需明确授权。
